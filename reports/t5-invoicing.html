What changed & why

All demo data stays in Convex seeds; UI pulls straight from queries. Five client-reviewed controls land in one coherent slice:

1 — Schema: separate Sales vs After-Sales + human numbers

  • convex/schema.ts: invoices.jobId → optional, added salesOrderId?, domain?:'service'|'sales', kind?:'estimate'|'final', invoiceNumber?:string (EST-YYYY-#### / INV-YYYY-####), status?:'draft'|'approved'|'rejected'|'converted', rejectedReason?, locked?:boolean, generatedById?; indexes salesOrderId + invoiceNumber; jobs.reversedReadyTs?; settings.nextEstSeq/nextInvSeq/estYear/invYear.
  • src/lib/enums.ts: INVOICE_DOMAINS/KINDS/STATUSES.
  • src/lib/schemas/invoice.ts: Zod schemas createEstimateSchema / rejectEstimateSchema / adminUnlockSchema.
  • Why: nullable linkage keeps legacy rows migratable (old invoices backfill as service/final), while new writes enforce domain==='service' ⇒ jobId vs sales ⇒ salesOrderId.

2 — Shared line-item builder kills duplication

  • New convex/lib/invoiceHelpers.ts: buildLineItemsForJob(ctx, jobId) (maps jobItems → descriptions via part.code - description / labourType.name, now Promise.all parallel), buildLineItemsForSalesOrder (single vehicle line at agreedPrice), nextInvoiceNumber(kind) (atomic counter on settings doc with yearly reset), assertNotLocked, findApprovedFinalForJob.
  • All of invoices.generate / generateSales / regenerate, jobs.syncInvoiceForJob, seedAdvanced now call the helper; VAT via shared computeInvoiceTotals(lineItems, vatRate). Removes the 4× copy-paste that previously was in generate/regenerate/sync.

3 — Estimates: CSR prepares, Finance governs

  • convex/invoices.ts: createEstimate (csr/manager/admin/salesRep, requires parent + ≥1 jobItem, assigns EST-YYYY-####), updateEstimate (refresh from parent, only draft + not locked), approveEstimate (finance/manager/admin), rejectEstimate (reason 3..300), convertEstimateToFinal (approved → new INV-YYYY-#### final draft copying totals, marks estimate converted, audits both). Estimates never lock.

4 — Reverse ready-for-pickup

  • convex/jobs.ts:reverseReady — requireRole(['manager','admin']), requires status==='readyForPickup' and no approved final (via findApprovedFinalForJob), patches status→inProgress, clears readyForPickupTs, sets reversedReadyTs, audit job.reverseReady.

5 — Lock after final approved

  • When kind==='final' && approved===true → locked=true + generatedById (+ approvedTs). Set in approve.
  • assertNotLocked enforced in jobs.addJobItem / removeJobItem, invoices.generate/regenerate, payments.record, and syncInvoiceForJob (early return if locked). payments.record also caps amount > remaining and blocks estimates.
  • invoices.adminUnlock — admin only, reason 10..300, locked=false, audit reason in action string.
  • generatedById projected only to admin (getByJob/listByJob/getById strip field for non-admin, return generatedBy join only when admin).
  • Scope cuts honored: no COGS, no commissions, no PDF redesign beyond estimate/locked banners.
Seed: convex/seedAdvanced.ts assigns INV-YYYY-0001..0003 to demo invoices, sets domain service, kind final, status approved, locked true, generatedById csr, and bumps settings.nextInvSeq past seeded numbers.

Regressions

  • Job not yet invoiced: adding parts/labour still auto-transitions to inProgress, no lock friction.
  • PrintableInvoice: estimate prints watermark, locked prints locked stamp, number header uses invoiceNumber.
  • SeedAdvanced still idempotent (marker part CLN-001 guard); legacy invoices backfill handled by optional fields.
  • Every new mutation writes auditLogs; search by entityId.
  • No mocked frontend data: all data via Convex queries.
  • Build + typecheck + unit tests remain green.

Mistakes made

  • Sequential N+1 for part/labour lookups — first helper used for … await ctx.db.get per item. Fixed to Promise.all parallel after plan-review F14 note; still O(n) but not serialized.
  • Leaked generatedById to non-admin — initial getByJob/listByJob returned raw invoice including generatedById for all roles. Fixed to strip for non-admin and only join when admin.
  • Badge variant typo — used variant="danger" not in design-system (should be destructive) causing type error. Fixed.
  • Sales invoice section missing — first pass only did after-sales; sales domain had no UI. Added minimal SalesInvoiceSection on order detail.
  • Committed bun.lock — bun install created bun.lock alongside pnpm-lock.yaml. Left in repo for reproducibility but flagged as noise; ideally .gitignore one or the other.
