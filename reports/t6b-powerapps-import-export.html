What the research doc actually argues (so the reviewer doesn't have to open it first)

Part A bottom line: Do not rebuild. A faithful Power Apps rebuild is 6–10 weeks + $20/user/month forever (plus Dataverse ~$40/GB overage) vs finishing this app in 10–15 days. Power Apps is wrong for: guarded state machine with 6 per-transition timestamps, deny-by-default 6-role matrix, immutable auditLogs, delegation-capped search, computed invoice → approve → payments → balance flow. If a Power App is contractually required, make it a thin 1–3 screen canvas companion that calls Convex HTTP actions via a custom connector (OpenAPI) and keeps Convex as system of record. Two strawmen killed: Dataverse mirror (eventual drift) and Excel/Power Automate glue (governance hostile).

Part B bottom line: Inventory first. Import: SheetJS Community client-side parse (File.arrayBuffer → XLSX.read → sheet_to_json → header aliases → per-row Zod createPartSchema → intra-file dup + by_code dedup) with preview table + policy skip|update|error (ship skip first). Export: client-side SheetJS write for every surface under ~5k rows; server Convex action + storage.store() only for the unbounded stock-movements audit. PDF: keep PrintableJobCard/Invoice print-CSS (zero bytes, already shipped); add jspdf + jspdf-autotable lazy for tabular list PDFs that need pagination/repeat-header/page numbers. Optional exceljs lazy for styled headers. One helper set reused across 9 surfaces, rollout table S/M/L, money stays kobo (moneyKobo), Zod re-parse on server, requireRole + audit() kept.
