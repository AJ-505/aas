How 2FA login works (no Password hook)

  1. Password sign-in via Convex Auth succeeds (session created).
  2. users.me returns totpEnabled + lastTotpVerifiedTs. AppShell detects needsTotp (30-min window) and <Navigate to="/auth/verify-2fa"> — no URL bypass (guard on every render).
  3. User enters code on /auth/verify-2fa → twoFactor.verifyLogin verifies TOTP (window ±1) or single-use backup code (consumed). On success patches lastTotpVerifiedTs + lastActiveTs = now.
  4. Server requireActiveSession also checks those timestamps on every write — replay after 30 min is rejected even if client routing was bypassed.
Design choice: Gated post-login, not a forked store or custom JWT. Convex Auth Password has no onSignIn hook; patching store would couple to internals and risk token drift. Post-login gate is reversible, testable, and keeps auth upgrade path clean.

Secret handling limits (documented)

totpSecret and backupCodes are stored plaintext in Convex DB. Convex encrypts at rest, but there is no per-field envelope encryption in this app — anyone with DB read can see them. Backup codes are single-use (spliced on use). No secret is ever logged; audit entries record only userId + action. This matches the PRD scope cut.
