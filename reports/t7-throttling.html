Throttling shipped — generous caps, no dead shift, real checkbox.

Client asked to enable throttling. We bound every write mutation with per-user aligned-window counters (one doc per user:class:window, composite index by_key_window). Ships enabled with an admin kill-switch, structured RATE_LIMITED/DEDUP errors, dedup on payments, and a Throttle tab in /admin/audit.

Enabled by default admin 5/min financial 20/min bulk 5/min standard 60/min DEDUP 60s on payments
Honest auth note — read before review: Convex Auth signIn/reset runs as HTTP routes (convex/http.ts + convex/auth.ts Password provider reset.maxAge=3600). Convex mutations have no Request/IP in ctx, so per-IP throttling inside mutations is not implementable there. We rate-limit what is possible: per-user after auth for every app mutation, per-email normalization if an HTTP wrapper is added later, and a client isPending debounce on login. The report documents the limitation plainly — no fake ip arg.

What changed & why

Schema (additive, no migration)

  • rateLimits {key, windowStart, count, actionClass} index by_key_window ["key","windowStart"] — one doc per user:class:window, new doc per window (no reset patch, no hot-row).
  • rateLimitEvents {key, actionClass, ts, limit, windowMs, retryAfterMs, userId} by_ts, by_actionClass — observability (best-effort, see caveat below).
  • settings.rateLimitEnabled?: boolean — default true when missing; admin toggle.

Library

New convex/lib/rateLimit.ts: windowStartFor(ts,w)=floor(ts/w)*w, isRateLimitEnabled(ctx) (settings + env), enforce(ctx, class, {now}) (query by_key_window → insert or patch or throw ConvexError {code:'RATE_LIMITED', retryAfterMs, limit, windowMs, actionClass}), enforceDedup(ctx, fingerprint, 60_000) (per-user fingerprint dedup, throws DEDUP). Laser docs: no scheduler on hot path.

Admin control & observability

  • convex/rateLimit.ts: listEvents (admin/manager/audit, desc by ts), getStatus, setEnabled (admin-only, audited), internal logEvent/cleanup.
  • convex/crons.ts: daily 03:00 UTC cleanup (events >30d, windows >24h).
  • src/lib/queries.ts: rateLimitQueries + useSetRateLimitEnabledMutation.
  • src/routes/admin/audit.tsx: new Throttle tab — events table (time, user, class, limit, retry, key) + footer truth about limits + kill-switch toggle.

Wiring — 34 mutations across 12 files

Each gets await enforce(ctx, class) after requireRole/requireActiveSession/getCurrentUser and before validation/business writes. Queries are never throttled (explicitly). payments.record also calls enforceDedup for identical invoiceId:amount:method.

Rollback caveat (documented): a thrown Convex mutation rolls back all writes in that transaction, so the rateLimitEvents insert before the throw is best-effort and will appear in convex-test harnesses but be rolled back in prod. The durable signals are the structured ConvexError (client toast + retry) and the auditLogs rateLimit.hit:* attempt (also best-effort) plus the live rateLimits buckets themselves. Future durability can move logging to a client-reported logEvent mutation after catch.

Synthesis we followed

Synthesized plan at /tmp/opencode/orch/t7-synthesis.md (10 decisions) + deep docs t7p1-t7p3. Decisions 1–10 above mirror it: lazy aligned window over @convex-dev/rate-limiter component (fallback we actually shipped — same semantics, no extra dep), every mutation, generous caps, enabled by default, structured errors, observability table + admin view, nightly GC, auth honesty, dedup, tests.

Why not the other options

  • Scheduled reset on hot path — rejected: floods scheduler, flaky tests, race at window edge.
  • Single global doc per class — rejected: OCC hot-row death (p50 doubles at 5 concurrent finance writers).
  • Relative reset (now - windowStart > w) — rejected: non-deterministic windows; we use floor(ts/w)*w.
  • Query throttling — rejected: hurts dashboard polling and search-as-you-type; queries are read-only.
