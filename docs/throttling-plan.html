# Engineering Position (Pushback)

Cedric Masters Autos is a single-tenant staff application deployed for one workshop's team. The typical threat model that motivates rate limiting — public signup, credential stuffing, scraping, bursty traffic from untrusted users — does not exist here: every caller is an authenticated employee with a role. Full-blown rate limiting would therefore be over-engineering. The honest recommendation is:

  • Do not build a general-purpose rate limiter across every mutation.
  • Do add two lightweight, high-value guards: (1) a soft cooldown on repeated financial mutations to absorb accidental double-clicks, and (2) limits on the auth/reset surface if it is ever exposed beyond the team.
  • Revisit only when a customer portal or public booking endpoint ships (both are post-MVP per the PRD).

The plan below is written so the team can adopt it fully, partially, or defer it with confidence.

03

Proposed Design

Mechanism — Fixed-Window Counter

  • New table rateLimits: { key, windowStart, count }, indexed on key.
  • Helper enforceLimit(ctx, key, limit, windowMs) called inside a mutation.
  • Read the row; if the window elapsed, reset; else if count ≥ limit throw ConvexError('Too many requests — try again shortly.'); else increment.
  • Atomic: Convex mutations run as single transactions, so check-and-increment cannot race.
  • Key scope: per userId (never a bare IP).

Housekeeping

  • Rows are reset in-place when a window expires — bounded size.
  • Optional nightly cleanup removes rows older than 24 h.
  • Feature-flag RATE_LIMIT_ENABLED (default false) so limits can be disabled instantly during demos without a deploy.
  • Limits are per-environment config, not hard-coded business rules.
// convex/lib/rate-limit.ts — proposed
export async function enforceLimit(
  ctx: MutationCtx,
  key: string,
  limit: number,
  windowMs: number,
) {
  const now = Date.now()
  const row = await ctx.db.query('rateLimits').withIndex('key', q => q.eq('key', key)).first()
  if (!row || now - row.windowStart > windowMs) {
    if (row) await ctx.db.patch(row._id, { windowStart: now, count: 1 })
    else await ctx.db.insert('rateLimits', { key, windowStart: now, count: 1 })
    return
  }
  if (row.count >= limit) {
    throw new ConvexError('Too many requests. Please wait a moment and try again.')
  }
  await ctx.db.patch(row._id, { count: row.count + 1 })
}

Client-Side Complement

Button cooldowns

Disable submit buttons while isPending (already the norm in this app) — the primary accidental-duplicate defence.

Input debounce

Debounce customer/part/lead search to ~300 ms to avoid a query per keystroke (pairs with CR-06).

Error copy

On a 429-style ConvexError, surface: "Too many requests — try again in a moment," never raw internals.
