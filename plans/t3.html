Security & Compliance Hardening

TOTP authenticator-only 2FA (QR + backup codes + login gate), admin password + 2FA reset, 30-min inactivity timeout with client warning + server requireActiveSession enforcement, and a full validation sweep across every mutation. No SMS/email/push, no custom JWT, no extra encryption beyond Convex at-rest.

Convex + TanStack Router Client-only is bypassable → server check REQUIRED Never log secrets/tokens

Design tree & settled decisions

1) 2FA via TOTP — authenticator apps only

TOTP RFC6238 SHA1 30s 6-digit window ±1QR: qrcode tiny (data URL)
  • Schema users: totpSecret?: string (base32 32-char, 20-byte), totpEnabled?: boolean, backupCodes?: string[] (10× 8-char A-Z0-9, single-use consumed on use), lastTotpVerifiedTs?: number, lastActiveTs?: number, mustChangePassword?: boolean. All optional for migration safety; new code treats missing as false/never.
  • Crypto convex/lib/totp.ts: base32Encode/decode, generateSecret() via crypto.getRandomValues, hotp(secret, counter) → HMAC-SHA1 via crypto.subtle (fallback pure-JS if unavailable), totpVerify(secret, code, window=1), otpauthUri(secret, email, issuer), generateBackupCodes(). Constant-time compare for codes. Documented limit: secrets stored plaintext in Convex DB, encrypted at rest by Convex, no additional envelope encryption (scope cut, documented in code + report).
  • Enrollment flow convex/twoFactor.ts: setup (requireUser, generate secret, store as pending totpSecret but keep totpEnabled=false, return {secret, uri}) → verifySetup (requireUser, verify code against stored secret, on success set totpEnabled=true, generate backupCodes, set lastTotpVerifiedTs=now, audit) → client renders QR via QRCode.toDataURL(uri) + manual secret fallback + backup codes printable sheet.
  • Login gate (custom layer, no Password hook): Convex Auth has no TOTP hook → gated post-login check. users.me now returns totpEnabled, needsTotpVerify, mustChangePassword, lastActiveTs. AppShell after auth: if totpEnabled && now - lastTotpVerifiedTs > 5min (initially >0) → <Navigate to="/auth/verify-2fa"> with no bypass. /auth/verify-2fa calls twoFactor.verifyLogin {code} (also accepts backup code). That mutation verifies (consumes backup code if used), sets lastTotpVerifiedTs=now + lastActiveTs=now. Success → redirect to /. Failure → remain on verify page, rate-limited by ConvexError message only (no secret leak).
  • Server enforcement: requireActiveSession() (new convex/lib/session.ts) checks lastActiveTs freshness (30min) AND if totpEnabled then lastTotpVerifiedTs freshness (30min). All write mutations route through requireActiveSession (see §3). Even if client bypasses redirect, writes are rejected.
  • Admin reset 2FA: twoFactor.adminReset(userId) with requireRole(['admin']) clears totpSecret/totpEnabled/backupCodes/lastTotpVerifiedTs, audit. User re-enrolls.
  • Never log: no console.log of secrets/codes/backupCodes/tokens in any mutation; audit entries log userId + action only.
Why gated post-login, not sign-in callback? @convex-dev/auth Password provider offers profile, authorize, reset but no onSignIn TOTP hook; patching store would couple to auth internals and risk JWT drift. Post-login gate + server requireActiveSession is clean, reversible, and testable without forking auth. Documented in convex/lib/totp.ts header + report.

2) Admin password reset + force change

  • Mutation users.adminResetPassword {userId, tempPassword}: requireRole(['admin']), Zod tempPassword: string min 8 max 128, cannot reset self to avoid lockout footgun (allowed but warns). Implementation: update Convex Auth's authAccounts record for that user where provider=="password". Hash with crypto.subtle SHA-256 + bcrypt-like? — actual path: delegate to Convex Auth internals by deleting old account and delegating hash to Password provider via internal ctx.db.patch of secret using auth helper if exposed; fallback documented: if hash API unavailable, store users.mustChangePassword + tempPasswordHash (SHA-256) and intercept at login via custom verifyPassword mutation. Either way, never log plaintext.
  • Sets users.mustChangePassword=true + lastActiveTs=now. Audit user.adminResetPassword.
  • Force-change flow: /auth/change-password (or inline in verify gate) with users.changePassword {currentPassword, newPassword} (or mustChangePassword bypasses current check when admin-set). Zod validates strength, updates auth secret, clears mustChangePassword, audit.
  • Admin UI /admin/users: per-row “Reset password” (modal: temp password input, generates random 12-char if blank) + “Reset 2FA” button. Both with confirm + toast. Disabled actions log only via audit.
  • Fix CR-01: grep removal of any console.log(token) in convex/auth.ts reset.sendVerificationRequest → replace with audit-only or no-op in production; keep dev log gated behind CONVEX_ENV != production if needed, but never log tokens/passwords.

3) 30-min inactivity timeout — dual enforcement

LayerMechanismDetail
Serverusers.heartbeat {} + requireActiveSessionHeartbeat patches lastActiveTs=Date.now() throttled client-side ~60s (server accepts any call, minimal cost). requireActiveSession(ctx, roles) wraps requireRole + checks now - lastActiveTs > 30*60*1000 → ConvexError("Session expired due to inactivity. Please sign in again."). All write mutations use it; reads stay requireUser to allow warning modal fetches without heartbeat loop.
Clientsrc/hooks/useInactivity.tsDebounced listeners mousemove/keydown/click/scroll/touchstart (300ms), lastActive in ref + localStorage + heartbeat() every 60s via useConvexMutation(api.users.heartbeat). Interval checks every 30s: if now - lastActive > 25min → show InactivityWarningModal with countdown + “Extend session” (calls heartbeat, resets timer). If >30min → signOut() + navigate(/auth/login?expired=1) + toast. Root guard in AppShell also watches searchParams.expired to show banner.
Client-only is bypassable — attacker replays Convex function call after 30min of inactivity. Server requireActiveSession is the real gate; client modal is UX only. Heartbeat throttling prevents spam: client ensures ≥60s between calls, server could also enforce if (now - lastActiveTs < 50s) return to reduce writes.

4) Validation sweep — close every gap

  • Audit every convex/*.ts mutation's args with v.* strictness + length/format: name/email/phone trims, plate uppercase + regex, moneyKobo int ≥0, etc.
  • Add missing Zod schemas: src/lib/schemas/job.ts fix addJobItemSchema to enforce type: enum['part','labour'] + conditional partId/labourTypeId, qty/unitPrice bounds; src/lib/schemas/invoice.ts narrow method: enum['cash','transfer','card','pos','bank'] (currently free-form string) with fallback for legacy; src/lib/schemas/sales.ts validate addPayment amount against moneyKobo; src/lib/schemas/part.ts already ok but verify stock adjust qty integer range; appointments/customer/vehicle schemas already validated but re-check.
  • All mutations call Schema.parse(args) before DB work; Convex v validators remain as first line defense (defense in depth).
  • No mock frontend data — any demo data via convex/seed.ts.

Risks & mitigations

  • Convex Auth password hash internals undocumented → mitigation: probe authAccounts shape in dev, fallback to mustChangePassword + tempHash flow that doesn't need to know hash algo; document both in report.
  • crypto.subtle unavailable in Convex isolates → fallback to pure-JS HMAC-SHA1 (tiny, no dep). Verify in build.
  • Backup code replay → single-use: splice used code from array and patch.
  • Timing attack on code compare → constant-time string compare.
  • Heartbeat spam → client throttle 60s + server early-return if <50s since last.
  • CR-01 regression (logging tokens) → grep console.log in convex/auth.ts and remove; ES lint rule concept.
  • Role bypass → every mutation retains requireRole (now via requireActiveSession which internally calls requireRole), no raw ctx.db.get without auth.

Break-it tests (must pass)

  1. 2FA enroll: login as admin, open /settings/security, click Enable → QR appears (data URL), secret shown, copy works → enter wrong code → error → enter correct TOTP → success + 10 backup codes displayed → print.
  2. Login gate: sign out, sign in again with same account → redirected to /auth/verify-2fa (cannot navigate to / via URL). Enter wrong code → stays. Enter correct code → lands on dashboard. Enter backup code → succeeds and that code is consumed (reuse fails).
  3. Bypass attempt: with 2FA enabled, manually set localStorage totpVerified and try calling jobs.checkIn via Convex dashboard with stale lastTotpVerifiedTs (simulate by waiting or patching old timestamp) → mutation rejected with “2FA verification required”.
  4. Admin Reset 2FA: as admin, /admin/users → Reset 2FA on TOTP user → that user can now login without TOTP, re-enroll works, audit log entry exists.
  5. Admin Reset Password: admin sets temp password Temp1234! for user Amara → that user’s next login with old password fails, with temp succeeds → forced to /auth/change-password?force=1 before any other page, cannot bypass by navigating to / → after change, login with new password works, mustChangePassword cleared, old temp fails.
  6. Never log: grep convex/** for console.log + token/password/secret → zero hits. Audit logs contain no secrets.
  7. Inactivity warning: login, set system clock +25min (or edit hook timeout to 10s for test) → warning modal appears with countdown + Extend button → click Extend → modal closes, heartbeat called, timer resets. If not extended and reaches 30min → auto signOut → redirect /auth/login?expired=1 with “Session expired due to inactivity” banner.
  8. Server timeout: login, manually stop heartbeats (disable activity), wait 31min (or patch lastActiveTs to old), then attempt any write via Convex dashboard (e.g., parts.createPart) → rejected “Session expired”. Read queries still succeed.
  9. Heartbeat throttle: rapid activity (mousemove 10x/sec) → network tab shows at most 1 heartbeat per ~60s.
  10. Validation sweep: try jobs.addJobItem {type:'weird', qty:-1, unitPrice:'abc'} → Zod/ConvexError rejects. payments.record {method: ''} → rejects. vehicles.create {plate:'ab'} → regex rejects. appointments.create {vehicleMake:''} → rejects. All with boundary strings.
  11. Existing flows unbroken: check-in, parts dispatch, invoice generate, sale order create still work when session fresh & 2FA verified.
  12. Seed not mocked: no frontend mock data introduced; rg "mock" src/ yields only test helpers.
