Design tree — settled defaults

Frontier exhausted autonomously; grill spawned via nohup opencode2

Q1 — Duplicate signal: throw or return?

Throw ConvexError with structured payload {message, existingCustomerId}. UI catches and offers “Use existing” CTA. Returning an ID would silently succeed and confuse callers expecting an ID.

Q2 — Name similarity definition

Normalize both names: trim → collapse whitespace → lower. Equal → similar. Else Levenshtein distance ≤2 (covers Chinedu vs Chinede, Amara vs Amarah). No library. Threshold tight to avoid false positives.

Q3 — Phone normalization boundary

Exactly trim() — no stripping of +234, spaces, dashes. Matches spec “no normalization lib”.

Q4 — Plate regex timing

Normalize first, then test ^[A-Z0-9][A-Z0-9 -]{2,}$. Reject with clear message. Empty plate stays undefined where optional.

Q5 — Appointment legacy migration

Schema makes customerId optional so old rows still read. Mutation enforces required. No data migration needed. Backfill plates only.

Q6 — Check-in race

Check-in reuses same customers.create guard. If two tabs race to create same phone, one wins, other gets duplicate error → retries by fetching existing. Convex OCC serializes.

Guard pattern: every mutation keeps requireRole + audit(). Plate mutation adds audit('vehicle.update',...) already present.

Indexes used

  • customers.by_phone (exact duplicate check) — indexed, not search
  • customers.name + search_phone search indexes (UI search)
  • vehicles.by_plate (uniqueness) — now stores uppercase only
  • appointments.appointmentTs range + status

4 — Risks & grill findings (answered)

  • False duplicate from phone exact + case-only name diff: tolerated — phone equality is the business identity; claiming two customers share one phone is legit to block. User shown “Use existing” CTA to merge.
  • Race on concurrent create with same phone: both read index before write; Convex serializes via OCC — second mutation retries and now sees duplicate → error. No lost duplicate.
  • Appointment legacy rows without customerId: UI guards new creates only; old rows render with fallback name ?? customer.name. No migration burn.
  • Plate case migration: byPlate index had lowercase keys; after flip we uppercase on read but old keys stay lowercase unless backfilled. Backfill rewrites them — until then lookup misses. Backfill must run before prod flip is considered complete.
  • Search UX bypass via direct API: covered — server guard is source of truth; UI gate is convenience only.
  • ConvexError shape drift: we use new ConvexError({message, existingCustomerId}) — client parses err.data?.existingCustomerId ?? parse from message defensively.
Adversarial plan reviews: two subagents (nohup opencode2) will verify index misuse, missing validators, RBAC gaps, and over-built UI. Findings checked against code before fixing.
