1) What we are building

1 — Audit role
Append audit to ROLES (order matters, at end). roleValidator auto‑picks it up via v.union(...ROLES.map(literal)). ROLE_LABELS.audit = 'Auditor'. Seed audit@cedricmastersautos.com / password123. users.list allows ['admin','audit']. AppShell canSee returns true for audit (full nav, read‑only). Top banner when audit active.
2 — Activity logs
New table activityLogs {userId?, email?, event, ts, userAgent?, browser?, device?, screenInfo?, ip?} with indexes by_user, by_ts, by_event. Events: login|logout|login_failed|session_expired|password_reset|totp_change|totp_enabled|totp_disabled. Mutation activityLogs.log accepts client UA/screen (honestly spoofable). UA→browser/device parsed server‑side via regex. IP only when passed from an HTTP action (pure Convex mutations have no request).
3 — Admin audit UI
/admin/audit route, admin‑only, two tabs: Business auditLogs + Activity activityLogs. Filters: user / action|event / date range / limit (50/100/250/500). Queries: auditLogs.list + activityLogs.list (both admin‑only, index‑aware). Honest capture note rendered in table footer.

4) Break‑it tests

  • Role smuggling — log in as audit, attempt every mutation (checkIn, diagnose, parts.createPart, invoices.generate, salesOrders.create) — expect ConvexError: not authorized.
  • Audit sees all nav — audit login → AppShell shows Dashboard, Appointments, Customers, Jobs, Inventory, Leads, Orders, Vehicles, Parts, Finance, User Management, Audit Log (all visible, read‑only banner shown).
  • Finance read‑only — audit visits /service/finance → VAT input disabled, no Save, labour Add hidden, Edit/Delete replaced by “Read‑only”.
  • Parts catalogue read‑only — audit visits /service/parts → no Add/Import/Manage brands, no row Actions.
  • Order actions hidden — audit visits /sales/order/$id pending → no Record Payment / Complete / Cancel.
  • Admin audit filters — admin at /admin/audit toggles tabs, filters by user/action/event/date/limit, sees combined honest capture note.
  • Activity log spoof — call activityLogs.log with crafted UA → browser/device parsed, stored, visible to admin.
  • Seed — convex/seed.ts creates audit@… / password123 idempotently.

5) Risks & cuts

  • Index fan‑out: activityLogs.list does take(limit*3) then in‑memory filter to keep queries simple; fine for <500 cap, avoids composite index explosion. If volume grows, add composite by_user+event later.
  • No IP pipeline: per scope cut, no retention/streaming. IP remains null for pure mutations — documented, not hidden.
  • Future mutation leak: if someone writes a mutation guarded only by requireUser, audit could write. Mitigation: review guideline + existing pattern is requireRole on all mutations.
