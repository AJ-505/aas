Plan — Research-only integration study

SharePoint Integration without pretending SharePoint is a Node host

The client wants to know how a Convex + TanStack Start app meets SharePoint. Answer honestly: it doesn't run inside SharePoint — it runs alongside it, behind Entra SSO, optionally syncing via Graph. This plan ensures the research doc earns enterprise trust.

Why this framing wins the room

An enterprise reviewer has seen ten proposals that say "we'll deploy to SharePoint via SPFx" without naming that SharePoint has no Node runtime, Convex is a BaaS, and TanStack Start needs Nitro. Calling that out in §2.1 immediately signals competence. Then the doc earns the right to recommend the pragmatic path: Azure-hosted Nitro + Convex + Entra SSO + optional Graph, with SPFx/Teams as a later embed — not a deployment.

What the doc must prove
  • Convex + Nitro cannot run inside SharePoint (no Node/SSR/WebSocket)
  • Least-privilege Graph: Sites.Selected over Sites.ReadWrite.All
  • Teams tab / Viva ACE beats SPFx iframe for most orgs
  • Licensing + compliance are priced, not hand-waved
What the doc must not do
  • Suggest hosting Convex functions inside SPFx (impossible)
  • Promise static SPA on SharePoint without naming SSR loss
  • Request tenant-wide scopes without justification
  • Hide SPFx version hell, approval latency, or cookie traps

Break-it tests — how to falsify this doc

If any of these pass against the doc's claims, the doc is wrong.

#ProbeExpected outcome if doc is correct
1Claim: "TanStack Start can static-export to SharePoint." Try vp build with SSR disabled — does Convex real-time still work without Nitro?Fails — Convex subscriptions need Convex endpoint; SSR guards break. Doc correctly calls this a strawman (§2.2/G).
2Claim: "Request Sites.ReadWrite.All for invoice archiving." Would tenant admin consent?Often denied — doc prescribes Sites.Selected (§3.2) and that is the test to run.
3Load the Azure-hosted app inside an SPFx iframe on Safari 17. Does Entra SSO persist?No — third-party cookie partition. Doc's §4.3 predicts this and offers pop-out fallback.
4Submit an SPFx .sppkg to a governed tenant's App Catalog on a Friday. Is it live Monday?Not necessarily — CAB window + approval. Doc's §4.4 prices 1–14 d wait.
5Mirror 6 000 jobs into a SharePoint List and create a filtered view.Hits 5 000 list-view threshold — doc's §3.4 warns and prescribes indexing.
6Let Graph deltaLink sit for 10 days then poll again.Expired — fallback to full scan. Doc's §3.4 names the 7-day expiry.
7Try Conditional Access (MFA) on a tenant with only Entra ID Free.Blocked at policy assignment — doc's §7.1 names P1/P2 requirement.
8Map an Entra group directly to users.role = "admin" without validation.Privilege escalation path — doc's §5.3 forbids auto-mapping.

Risks & explicit traps we avoid

Trap: "Deploy Convex + Nitro inside SharePoint" — Architecturally impossible (see §2.1). Any design that tables this loses credibility. The doc rules it out in one paragraph and moves on.
Trap: Auth cookies in iframe — Convex session + Entra cookies are third-party inside an iframe. The doc does not hide this; it names SameSite/ITP and offers the pop-out + Teams SSO alternative (§4.3).
Trap: Blanket Graph scopes — Sites.ReadWrite.All without per-site justification will be rejected by a least-privilege reviewer. The doc uses Sites.Selected throughout and keeps the broad scope as a flagged alternative.
